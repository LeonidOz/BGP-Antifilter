# Списки, настройки и обслуживание

[Установка](../README.md) | [MikroTik](mikrotik.md) | [English](usage.en.md)

Инструкция рассчитана на установку из готового образа по README.
Команды выполняйте в папке с `compose.yaml` и `.env`.
Для Portainer те же действия с контейнером выполняются через его интерфейс.

## Изменение списков

Откройте **Списки** в веб-панели, измените нужный список и нажмите **Сохранить**.
На панели нажмите **Проверить изменения**, затем **Обновить маршруты**.
Первая кнопка проверяет результат без применения; вторая загружает списки и применяет новые маршруты.
Дальше они обновляются автоматически каждые 30 минут.

| Что нужно добавить | Где указать | Пример |
| --- | --- | --- |
| Готовый список IP и подсетей | Источники IP, `lists.txt` | URL текстового или JSON-списка |
| Готовый список доменов | Источники во вкладке добавляемых доменов, `domain-list-urls.txt` | URL файла с одним доменом в строке |
| Отдельный домен | Добавляемые домены, `include-domains.txt` | `example.org` |
| Подсети организации по ASN | ASN, `include-asns.txt` | `AS32934` |
| Подсети страны | Страны, `include-countries.txt` | Выберите страну в панели; в файле хранится код `DE` |
| Домен, который нужно исключить | Исключаемые домены, `exclude-domains.txt` | `example.net` |

В текстовых списках пишите по одному значению на строку. Пустые строки и строки с `#` пропускаются.
Для URL можно указать понятное имя: `Название | https://example.org/list.txt`.

В списках доменов указывайте сами имена, без `https://`, путей и `*.`.
Загружаемый список доменов также должен содержать только имена:
форматы Adblock и hosts не поддерживаются.
Приложение добавляет найденные IPv4-адреса; оно не строит полный список всех поддоменов сайта.
Проверить конкретный IP или домен можно в разделе **Инструменты**.

При первой установке стандартные списки создаются автоматически.
Свои изменения сохраняйте через панель: они остаются при обновлении приложения.
По умолчанию также включены диапазоны сервисов Google за вычетом Google Cloud.

### Если источник недоступен

Приложение использует кеш не старше 7 дней. Если подходящего кеша нет:

- Недоступный IP-список или список доменов пропускается; обновление возможно по остальным данным.
- Неразрешившийся добавляемый домен пропускается.
- Неразрешившийся исключаемый домен останавливает обновление, чтобы не вернуть исключённый адрес.
- При `REQUIRE_ALL_URL_SOURCES=1` недоступный URL-список тоже останавливает обновление.

Если новый набор маршрутов не удалось подготовить или применить, остаётся предыдущий рабочий набор.
При первом запуске такого набора ещё нет — для старта нужны доступные источники и DNS.

## Настройки

Адреса BGP и пароль задаются при установке в `.env` или переменных Portainer.
После изменения `.env` выполните `docker compose up -d`: обычный `restart`
не перечитывает окружение Docker.

Остальные параметры удобнее менять в разделе **Настройки** веб-панели:

| Параметр | По умолчанию | Для чего |
| --- | --- | --- |
| `UPDATE_INTERVAL` | `1800` | Интервал обновления в секундах |
| `CACHE_MAX_AGE` | `604800` | Сколько секунд можно использовать кеш: 7 дней |
| `REQUIRE_ALL_URL_SOURCES` | `0` | Значение `1` требует доступности каждого URL-источника или его свежего кеша |
| `DNS_RESOLVERS` | Системный DNS | Свои IPv4 DNS-серверы через пробел или запятую |
| `DNS_RESOLVE_TIMEOUT` | `3` | Ожидание DNS-ответа в секундах |
| `FETCH_TIMEOUT` | `30` | Ожидание загрузки источника в секундах |
| `FETCH_ATTEMPTS` | `5` | Число попыток загрузки источника |
| `FETCH_RETRY_DELAY` | `5` | Пауза между попытками в секундах |
| `MIN_PREFIX_LENGTH` | `8` | Защита от слишком широких маршрутов |
| `ALLOW_BROAD_ROUTES` | `0` | Оставьте защиту включённой |

Сохраните изменения и нажмите **Применить сейчас**.
Параметры BGP с пометкой «перезапуск» требуют перезапуска контейнера;
для установки из README — `docker compose restart`.
Сохранённые в панели значения имеют приоритет над одноимёнными значениями окружения:
если меняли параметр в панели, продолжайте менять его там.

Дополнительные параметры файла `.env`:

| Параметр | По умолчанию | Когда менять |
| --- | --- | --- |
| `ADMIN_PORT` | `8080` | Если порт панели занят |
| `HEALTHCHECK_REQUIRE_BGP` | `1` | Поставьте `0`, если используете только выгрузку Address List |
| `HEALTHCHECK_FAIL_ON_DEGRADED` | `0` | Поставьте `1`, если ошибка обновления должна менять статус Docker на `unhealthy` |
| `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` | Без прокси | Если серверу нужен прокси для загрузки источников |

При использовании прокси перечислите локальные адреса в `NO_PROXY`.
Пользовательские `DNS_RESOLVERS` включают прямую загрузку источников с собственным разрешением DNS;
HTTP-прокси в этом режиме обходится.

## Обновление приложения

Обновление списков происходит автоматически. Новую версию самого приложения устанавливайте отдельно.

Для установки из README:

1. Сохраните резервную копию данных по инструкции ниже.
2. Измените `BGP_ANTIFILTER_VERSION` в `.env` на нужную версию.
3. Выполните:

```bash
docker compose pull
docker compose up -d
docker compose ps
```

Списки и настройки сохраняются в томе `bgp-antifilter-config`,
маршруты и кеш — в `bgp-antifilter-data`.
Для возврата на предыдущий образ укажите его версию и повторите эти команды.
В Portainer меняйте `BGP_ANTIFILTER_IMAGE` и обновляйте стек с повторным скачиванием образа.
Встроенная установка обновлений через панель для этого стека отключена.

Для обычной установки выбирайте тег версии или `latest` — последний стабильный релиз.
`edge` и `sha-<коммит>` предназначены для проверки изменений.

### Где хранятся данные

Таблица описывает схему хранения начиная с [0.5.2](../CHANGELOG.md#052---2026-11-13).
Для прежних установок см. [переход к раздельному хранению](#переход-к-раздельному-хранению).

| Путь в контейнере | Что хранится | Готовый образ / исходники |
| --- | --- | --- |
| `/etc/bird/config` | Пользовательские списки, `settings.json`, `settings.env`, `list-backups/` и метка миграции | Том `bgp-antifilter-config` / папка `config/` |
| `/etc/bird/generated` | Маршруты, последний рабочий набор, кеш, состояние обновлений, метрики и логи | Том `bgp-antifilter-data` / папка `generated/` |

`settings.json` хранит настройки из панели, а `settings.env` передаёт их служебным скриптам.
Сохраняйте и восстанавливайте эти файлы вместе; обычно редактировать их вручную не требуется.
Файл `.env` и Compose-файл находятся на сервере отдельно от томов и тоже нужны для восстановления.
Имена томов можно изменить переменными `BGP_CONFIG_VOLUME` и `BGP_DATA_VOLUME`.

### Резервная копия

Выполните из папки установки; для каждой копии используйте новое имя папки:

```bash
docker compose stop
mkdir -p backup
docker compose cp bgp-antifilter:/etc/bird/config ./backup/config
docker compose cp bgp-antifilter:/etc/bird/generated ./backup/generated
cp .env compose.yaml ./backup/
docker compose start
```

Сохраните всю папку `backup`, включая скрытый файл `.env`.
При переносе нужны настройки подключения и оба тома: `bgp-antifilter-config`
с пользовательскими списками/настройками и `bgp-antifilter-data` с маршрутами и кешем.
В установке из исходников это соответственно папки `config/` и `generated/`.

Для остановки приложения используйте `docker compose down`.
**Не добавляйте `-v`, если хотите сохранить данные:** этот флаг удаляет тома стека.

Для восстановления установки из README верните сохранённые `.env` и `compose.yaml`
в папку установки. Создайте контейнер и тома, скопируйте данные в остановленный контейнер,
затем запустите приложение:

```bash
docker compose pull
docker compose create
docker compose stop
docker compose cp ./backup/config/. bgp-antifilter:/etc/bird/config
docker compose cp ./backup/generated/. bgp-antifilter:/etc/bird/generated
docker compose start
docker compose ps
```

Восстанавливайте в пустые тома или предварительно сохраните текущее содержимое:
`docker compose cp` заменяет совпадающие файлы, но не удаляет лишние.
Копируйте каталоги целиком, включая `.migration-v1.json`, затем проверьте настройки и маршруты в панели.

### Переход к раздельному хранению

Автоматическая миграция доступна начиная с [0.5.2](../CHANGELOG.md#052---2026-11-13).
В образе `0.5.1` её ещё нет: для перехода используйте образ `0.5.2` или новее
и файл запуска с двумя томами, как описано ниже.

Для старой установки перед первым обновлением остановите приложение и скопируйте
`/etc/bird/generated` из контейнера в отдельную резервную папку; также сохраните `.env`
и используемый Compose-файл или экспорт стека Portainer.
Затем обновите образ до версии с миграцией и обновите используемый YAML до схемы
с двумя монтированиями: `/etc/bird/config` и `/etc/bird/generated`.
Для Portainer используйте [новый файл стека](../deploy/portainer-stack.yml).
Имя прежнего тома `BGP_DATA_VOLUME` оставьте прежним. Новый том задаётся через
`BGP_CONFIG_VOLUME`, по умолчанию `bgp-antifilter-config`.
В установке из исходников сохраняйте папку `generated/`; новый Compose создаст рядом `config/`.

При первом старте до загрузки настроек и дефолтов приложение копирует:

- списки и дополнительные файлы из прежнего `generated/config/`;
- `generated/settings.json` и `generated/settings.env`;
- резервные копии из `generated/list-backups/`.

Существующие файлы в новом каталоге, включая пустые списки, имеют приоритет.
Оригиналы не удаляются, маршруты и кеш остаются на прежних путях.
После успешного копирования в каталоге конфигурации появляется `.migration-v1.json`;
не удаляйте эту метку при обычном сбросе настроек, чтобы не импортировать старые значения повторно.
Проверьте списки и настройки в панели, затем запуск, обновление маршрутов и наличие резервных копий.

При откате образа оставьте новый YAML и оба тома. Предыдущие образы с поддержкой
`LISTS_FILE`, `SETTINGS_FILE` и `SETTINGS_ENV_FILE` используют указанные там новые пути.
Возврат старого YAML снова подключит старые копии настроек, без правок после миграции.
Если обновлять только образ со старым YAML, явно заданные старые пути сохраняются;
раздельное хранение включается после обновления самого стека.

Собственные источники `file://` сохраняют записанные в списках пути.
Если файл лежал в `generated/`, перед очисткой этого каталога перенесите источник в
`/etc/bird/config` и исправьте его URL в панели. При удалении кеша и рабочих маршрутов
следующий запуск снова потребует доступности всех необходимых источников и DNS.

## Если что-то не работает

Сначала откройте состояние источников и логи в веб-панели.
Если панель недоступна:

```bash
docker compose ps
docker compose logs --tail=100
```

| Проблема | Что проверить |
| --- | --- |
| Панель не открывается | Завершилась ли первая загрузка; адрес сервера, `ADMIN_PORT`, пароль и доступ через firewall |
| Ошибка `BIRD_IP is not assigned` | Адрес из `BIRD_IP` должен быть назначен Linux-серверу; посмотрите `ip -4 addr` |
| BGP не устанавливается | Совпадают ли адреса и AS с настройками MikroTik; доступен ли TCP 179 между сервером и роутером |
| Контейнер `unhealthy` | Закончилось ли создание маршрутов и установлена ли BGP-сессия; для Address List задайте `HEALTHCHECK_REQUIRE_BGP=0` |
| Новые маршруты не применились | Ошибки URL/DNS и исключаемых доменов; откройте подробности последней операции |
| Маршруты есть, сайт недоступен | Попал ли нужный IP в список; выбран ли VPN-шлюз на MikroTik; работают ли VPN, NAT и правила FastTrack |

Команды для дополнительной проверки:

```bash
docker compose exec bgp-antifilter birdc show protocols
docker compose exec bgp-antifilter /check-ip.py 1.2.3.4
docker compose exec bgp-antifilter /update-routes.py --check-sources
docker compose exec bgp-antifilter /update-routes.py --dry-run
docker compose exec bgp-antifilter /reload-routes.sh
```

Последняя команда применяет маршруты; предыдущие проверяют состояние и данные.
`--dry-run` может обновить кеш источников, но не применяет маршруты.

Если нужны файлы для разбора ошибки, они находятся в `/etc/bird/generated` внутри контейнера:
`status.json` — источники и результат обновления, `runtime.json` — ход операции,
`network-status.json` — адреса сервера, `metrics.prom` — метрики.
`routes.last-good.conf` хранит предыдущий подтверждённый набор до успешного применения нового.
